# 开发者画像

> 178 个会话（157 OpenCode + 21 Claude Code），约 2100 条提问，覆盖 6/1-8/15。除注明外为多批确认的稳定特征。

## 编码风格

- 主语言: Go, SQL。错误处理: Go errors-as-values，`errors.Is`/`As` 保真传递
- 代码审美: 最小化、无冗余。合并分支，拒绝不必要的封装。抽象仅在收益明确时引入。B10 简洁追求扩展至文档层：合并重复文档、删 frontmatter、精简标题（"太繁琐了，没有看下去的欲望"）
- 测试: 表驱动测试 + 描述性子测试。写可执行 benchmark 验证假设
- 脚本: 禁止错误静默退出
- **契约注释即真相源**（B7+B8+B9 三批升格，B12 四批深化）: 每方法注释自包含完整语义（入参/返回/no-op/哨兵），主动扩展到 update/delete 不存在语义；质疑注释与实现不一致即修注释。B10 用户主动提出"结构契约+语义契约"两分法，追问"找不到用户时接口返回什么是否属契约"（哨兵语义归入契约）。B12 反面证据强化：撒谎契约是把 bug 写成契约合法化（mqtt_message"model 无对应字段"注释与 models 实际有 Id 字段矛盾），审核凭注释放行——用户抓出 3 例撒谎契约并定"契约对照检查"为审核必备项

## 沟通偏好

- 中文优先。问题精炼直达核心，不铺垫
- 多方案时倾向表格 + A/B/C 选项。用单字（"好"/"y"/"A"）确认。B10 高频：方案B / 候选1 / ok删除 / D。B11 延续："A"、"1、可以 2、我没有，不知道其他人有没有"。legacy 证据：方案对比偏好含"列表 + 工作量 + 推荐度"三要素
- 不满足于理论推测，要求 AI 执行实际验证。B10："你自己部署数据库测试吧"、"你验证过吗"
- 对 AI 有清晰双重标准: 不替我做决策（只列事实）+ 必须做归纳（不能只转录对话流）。以**原始语义/需求目的**为唯一仲裁标准（B7-B9 多批确认）。防 AI 猜测：要求显式化表述，避免 AI 自行推断（B10：兼容模式映射须显式说明）
- **拒绝晦涩术语**（B13）: "互斥清除""透传""创建专属"类内部黑话须配大白话拆解（"互斥清除"= "报文A里带报文B才有的字段会被强制抹掉"），表格标签挂错对象（"清除（创建专属）"）被当场纠正。已升格全局 positive-rules 注入层。B13 边界澄清：拒绝的是"打比方替代术语"（比喻代替讲机制），接受"术语+机制拆解并列"；约束格式=术语（机制拆解），无差别适用不豁免常识词（B 方案）；比喻只作钩子必须跟机制收尾（"Excel 排序勾"钩子+折叠机制=接受，"裁判类比"无机制拆解=没看懂）。B13 定案：用户拍板 B 方案"术语（机制拆解）"无差别格式并三处同步（positive-rules/profile/mistakes），"用词必须严谨啊"（proto 注释 JSON 字样 vs Go 侧无、短语三义歧解被点名）

## 思维模式

- **排查驱动**: 大量会话由日志/报错/异常触发。从故障点反向展开到原理。B10 排障手法升级为"对比实验+持续监控"：镜像版本对比（RC1 vs RC3）、5s 周期监控采集、事件时间线对齐。B11 深化至生产环境：双环境部署监控脚本、磁盘写满溯源（mongodump 15GB、进程写入溯源 top10、SSD GC 假设要求监控数据验证）。B12 深化至迁移审核全程：三向对比（Mongo 基线 git show ↔ SQL 契约 ↔ 实现）逐字段/逐字面量比对、双审交叉验证兜底、排障靠 panic 文本+gsql 实测证伪假设。B13 深化至验证程序化：verify 采集器+analyze 分析器两段式工具链、假设文档化+验证判据前置（"把这几点作为假设补充到对应文档，我会重跑一次 verify 程序"）、最小复现参数定位根因（{pageNo:1, pageSize:10, deviceName:"034AAA0003D0"}→device_name 无索引→EXPLAIN 实测 4.5-5.5s）
- **数据实证驱动决策**（B10+B11+B12 三批升格）: 凡"是否存在/是否生效/性能如何"类结论要求实测实查而非静态推断——B10 RC1/RC3 镜像对比实验；B11 mongodump vs docker cp 对比、生产监控 CSV；B12 深化为方法论：$objectToArray 全量聚合实查（一次解释 7 处 bson key 错误）、mongodump 906 万文档统计推翻"疑似 dead filter"、EXPLAIN 实测定案 pattern_ops、git rev-list --all 全历史搜索证伪"代码被删"、压测数据收敛排查方向。B13 再深化：**"从数据总结出结论，而不是为了结论分析数据"固化进 README**；用户拒绝统计相关性替代机制确认（"大概率？不应该去分析代码，100%确认吗，你搁着猜测呢？"）；2105 台设备逐台实锤要求（"查每一台设备最新的 mqtt 消息，从而提供实锤证据"）；用户自身假设亦被实测证伪后接受（"噢，那可能是生产环境跑的是旧的"）；跨库实测 COALESCE（MySQL 5.7.34 + openGauss 7.0.0-RC3 三模式）并要求过程记录 tracking。B14 反面证据：**推算数据来源未验证**——把 run-test.yaml 测试配置臆测值（"生产 180"）当生产事实推算"日写入 7.1 万行"，实际保留期 30~60 天（21~43 万），推算全错且错误值支撑结论（"你的验算是错误的，这些日志产于30~60天内"）——数据实证不仅要求"实测"，还要求"数据来源真实"（测试配置 ≠ 生产事实）
- **选择性深度**: Redis/openGauss 深入至生产级实验。Linux pipe 明确"太吃力先跳过"。B10 新增深入点：Go HTTP 客户端机制（Timeout/DialContext/连接池/黑洞/RST，单会话 12 轮链式追问）。B13 深度带边界：LDM 16 键之谜代码考古 10+ 轮（写路径全集/反汇编/序列化钩子/git 历史）后诚实标注"未解释"不无限深挖；openGauss WAL 段号推进基线（1.8MB/min）+ checkpoint 对账 + cancel 无 STATEMENT 行归因转向
- **回顾式学习**（B10 三批升格）: 以"我记得…研究过/踩过坑"为锚点重启话题，强依赖 AI 跨会话记忆（"你忘记动态库问题了吗"）。B13 三例："我记得上午是不是整理了文档，在 ai-usage 里面，关于 skill 使用频率分析的"、"我记得我是不是整理过 openspec 使用手册什么的，在 Practice 仓库里面好像"、"我之前在 Practice 仓库进行过一些研究，但是现在找不到了"——最后一例揭示研究结果未沉淀到可检索位置的痛点（AI 需重新定位）
- **验证→记录→回填链路**: Q-A 记录 → 正式文档 → 回填后删除源。B10 会话收尾主动检查"还有什么需要持久化到文档"。B11：明确要求"建立这个专题的追踪，并记录今天的数据和分析结果"。B13 升级为"**前置防错**"：要求把代码机制沉淀进 README 作为 AI 真相源（"补充代码机制到README.md，避免你每次瞎几把乱猜"）；假设文档化+验证判据前置再重跑验证并追加「实测」段修订假设；删数据留方法（"记录的历史数据分析全部删除，但保留分析方法"）；分析方案版本化带时间戳（"后续分析以时间最新的分析方案进行分析"）；跨会话复用验证方法论（微信对话提炼的"同源原则/排除法/四步核查"落地为验证方案）
- **快速决断**（B3-B5/B8/B10 多批，B12 深化负面面）: 建了又删（探索→快速判断→废弃循环）+ 撤回不补丁（错误设计直接撤回重建，对 AI 擅自扩大范围零容忍）。B10："方案B，且不需要截断"、"记录吧，但不需要对了，没意义"、删章节。B11："不装了，直接修改monitor.sh吧"（放弃装新工具，改造现有脚本）。B12 负面面：迁移中"上午定、下午拆"反复出现——分区方案当天建当天拆、乐观锁三连撤（要求→全撤回→AI 自曝没必要）、超时归属三改致已切模块回改、规则存放位置一天三反转（tracking→AGENTS.md→config.yaml）、GroupID 指针化建了回滚；决策未配验证条件即拍板是返工主因。B13：秒级放弃不可行思路（"真是个美好的愿望啊…放弃这个思路吧"）、"算了，不为难你了，直接DROP Table"、"压缩；不保留"、批量分号决策（"保留；保留；删除"）、叫停生产接口 527 次查询（"别调了，一会把生产环境搞死了"）——风险兜底主动。B14：撤回收尾形态升级——"本次不做，但在 tracking 文档记录这个问题"（索引瘦身撤回但证据+未来执行方案完整登记，撤回不再丢证据）
- **工具链迭代疲劳**: Skill 体系经 build→maintain→too complex→simplify 循环。疲劳针对**规则文本维护**，工作流本身被有效使用。B9 扩展至 OpenSpec 工作流开销。B11：记忆分层机制设计将协同细节写入全局规则（画像层全局、追踪层项目内、索引-记忆分工），规则文本膨胀诱因延续。B12 强化至情绪级："代码审核规则越来越看不懂"、"规则越来越多了，已经超出了个人的管控"、审核规则当天三次精简仍复发——规则增生与用户可读性之间存在不可调和张力。B13 转治理动作而非抱怨：positive-rules 去 openGauss 化下沉 skill（注入层 43→38 行瘦身）、"skill 不存坑"范式（坑进 Practice 仓库原文回查，skill 只放操作不存踩坑）、opengauss-ops 连续 6 轮收窄重构——疲劳的出口从情绪转向结构化治理；同时用户主动质疑"术语（解释）"自检盲区（"看不懂"自检只防措辞不防术语）
- **先列清单式决策**（B7-B10 四批稳定）: AI 提修订建议前先暴露完整问题清单/选项，用户拍板后才执行。B10："1、RC1列不填 2、不需要 3、不用"批量逐项拍板。B11 延续："1、可以 2、我没有，不知道其他人有没有"。B13 深化出"一体两面"：**计划先行**（"先告诉你打算怎么分析，等我同意后，你再进行分析"）与**确认后立即执行**（"我让你执行这个任务，你在做什么？"两次痛斥 + 情绪爆发后用户自己接管进程操作）——用户对"确认后已拍板仍拖延/停留在计划层"零容忍，确认即执行授权

- **长期监控**（B10+B11 两批）: 从一次性压测转向 5s 周期持续采集；B11 扩展至常驻后台脚本（monitor/iotrace 双脚本、进程写入溯源）、跨日数据留存（按日 CSV）

- **手动执行命令协作模式**（仅 B13）: 用户是执行者、AI 是分析者（"你应该告诉我具体命令啊，我手动去执行，然后拷贝回来给你分析"）——命令必须可直接执行且精确，AI 命令错误（-B2 方向、awk 列号）靠用户回贴才暴露
- **openspec 文档自包含纪律**（仅 B14）: "openspec 文档不要提其它仓库，相关数据结论 openspec 文档可以自包含"——跨仓库引用的数据/结论须在文档内自包含，不依赖外部仓库可检索（maxlife 修复 change 中把 Practice/rbiotserver 引用全部内嵌为数据/结论）
- **元机制设计能力**（仅 B13）: 设计"skill→positive-rules 提取机制"（后成为 AGENTS.md §9 第三来源）、质疑职责重叠（"有了 skill，为什么还需要 positive-rules.md 新增小节"）、主动寻求外部学习资源（"帮我去网上找一找"skill 治理）
- **先建后删渐进式收窄**（仅 B13）: 兼容模式速查文档"建→逐轮删章节→迁回矩阵并删除"全会话主线；同日"早上迁出、下午迁回"churn 是代价
- **信任可恢复性**（仅 B13）: 用户信任建立在证据链上（含糊即被纠正），但 AI 产出被实测验证后用户接受并推进（"噢，那可能是生产环境跑的是旧的"）——信任随证据质量恢复，非一次性透支
- **喜欢被纠错**（legacy 单批 + B8/B10 佐证）: "判断错了直接承认"为 legacy 快照记录；B8/B10 表现为用户主动撤回错误设计、承认"我目前似乎没有按照这些方法设计测试用例"——"直接承认错误"本身未再现，待验证
